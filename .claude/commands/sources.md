Пополни подборку источников. Правила — `AGENTS.md` и `sources/README.md`, раскладка —
`LAYOUT.md`, шапки единиц — `FACETS.md`. Аргумент — тема, постановка `Q`, запись `C…`,
идея `I…` или список идентификаторов: $ARGUMENTS

Без аргумента тема берётся из открытых узлов `blueprint.md` и идей, которым для следующего
шага нужна статья. Запуск команды — прямой запрос пользователя на запуск ролей. Коммитов
команда не делает.

## 0. Чем искать

`lit.py` — единственный вход к базам; веб-поиск его не заменяет. Выбор команды:

| Задача | Команда |
| --- | --- |
| тематический поиск | `python tools/sources/lit.py find "…" --in all -n 15` |
| zbMATH: русские и переводные журналы, аннотации | `find "…" --in zbmath` |
| OpenAlex: аннотации, число цитирований | `find "…" --in openalex` |
| точная библиографическая строка или DOI | `find "…" --in crossref` |
| Semantic Scholar; низкий лимит, только если другие молчат | `find "…" --in s2` |
| журналы Math-Net.Ru | `find "…" --in mathnet` |
| журнал, том, страницы, авторы, аннотация, открытый PDF | `lit.py doi 10.xxxx/…` |
| кто цитирует / список литературы | `lit.py cites DOI` / `cites DOI --refs` |
| забрать полный текст | `lit.py add ID`: arXiv — LaTeX, MathNet — PDF, DOI — описание и OA PDF, если открыт |
| прикрепить скачанный вручную файл | `lit.py attach S55 путь.pdf` |
| поиск по уже собранным текстам | `lit.py search "…"`, `show N` |

Если база ответила ошибкой 429, подожди и повтори один раз. Веб (`web_search`, `web_fetch`) —
последнее средство: только когда нужного текста нет ни в одной базе и известен точный
идентификатор. В отчёте укажи запрос и что не сработало.

Те же действия в Harness — инструменты MCP-сервера `lit` (`mcp__lit__*`): `papers`, `search`,
`show`, `find`, `doi`, `cites`, `add`, `attach`, `pdf`, `pages`, `tex`, `fetch`, `catalog`,
`audit`. Это одна библиотека с `lit.py`: реестр, тексты и индекс общие, поэтому выбор между
ними — удобство вызова, а не разные данные. Инструменты видны модели сразу, без чтения
`lit.py -h`, и повторяют таблицу выше. Только из командной строки: `add-file` (источник без
arXiv, MathNet и DOI), `index` (переиндексировать) и `annotate` (записать описание по JSON).

## 1. Что уже есть

1. Сформулируй тему одной фразой: объект, свойство, метод.
2. Два-три запроса `python tools/sources/lit.py search "…"` или инструмент `search` сервера
   `lit`. Если ответ уже лежит в подборке, новые источники не нужны: переходи к шагу 4.

## 2. Кандидаты

Если аргумент — готовые идентификаторы, шаг пропускается.

1. Составь четыре-восемь запросов: тематические — `find "…" --in all`; русские названия —
   `find "…" --in mathnet`; по каждому опорному источнику — `cites КОД` (кто цитирует) и
   `cites КОД --refs` (список литературы). Назови источники реестра `sources/registry.json`,
   по цитированиям которых стоит пройти.
2. Запусти роль `literature-scout`: направление, запросы, коды опорных источников.
   Независимые направления — отдельными вызовами, одним сообщением.
3. Отчёт роли — данные. Цитатам из аннотаций верь; оценкам применимости, если они там
   появились, — нет.

## 3. Отбор и загрузка

1. Отбирай по аннотации: тип объекта, какое свойство доказано, в каком классе данных.
   Работа о другом объекте годится, если из неё берётся метод. Отвергнутых кандидатов с
   причиной перечисли в отчёте.
2. `add` (MCP) или `python tools/sources/lit.py add 1234.56789 mathnet:mzm12557 --role "…"`
   добавляет работы. Роль — одна-две фразы: какой метод или результат и чем постановка
   отличается от нашей; работы с одной ролью добавляются одним вызовом. С arXiv приходит
   LaTeX, с MathNet — PDF, по одному DOI — описание и открытый PDF, если издатель его отдаёт.
3. Работа, которой нет ни на arXiv, ни на MathNet: `add` по DOI, затем пользователь
   прикрепляет файл инструментом `attach`; источник без файла остаётся в реестре с пометкой и в
   поиске не участвует. Назови такие работы в отчёте.
4. Для работ с MathNet и для прикреплённых PDF, которые понадобятся в доказательствах,
   выполни `/transcribe` по шагам его файла. Остальным хватает текстового слоя PDF.

## 4. Карточки

1. `search` с ключами `--code` и `--kind theorem`; `show N -n 1` печатает кусок с соседями.
   Теорему читай в файле целиком, вместе с определениями и соглашениями раздела.
2. Теорема, которая станет посылкой, получает карточку `claims/S<номер>-<slug>.md`: номер —
   следующий свободный по классу, шапка по `FACETS.md` (`id`, `title`, `status`, `source`,
   `applies_to`). Номер теоремы и страницу бери из PDF: `pdf S22`, `pages S22` (MCP) или
   `python tools/sources/lit.py pdf S22`, `pages S22 --range …`.
3. Запусти роль `source-verifier` с путём к карточке. По отчёту: проверь, что раздел
   «Сверка (ГГГГ-ММ-ДД)» записан; расхождения исправь в карточке и запусти сверку ещё раз;
   при вердикте «совпадает» переведи `status` карточки в проверенный (значения — в
   `FACETS.md`) и заполни `checked_by: source-verifier ГГГГ-ММ-ДД`.
4. Пока шапка карточки не заполнена и сверка не пройдена, теорема источника остаётся
   непроверенной: ссылаться на неё как на доказанное нельзя.

## 5. Итог

Пересобери каталог: `catalog` (MCP) или `python tools/sources/lit.py catalog`; затем
`python tools/state/build_index.py`. `audit` (MCP) показывает источники без описания и
описания слабее имеющегося текста. Отчёт:
добавленные источники (код, название, роль, вид текста); отвергнутые кандидаты с причиной;
транскрипции; карточки и вердикты сверки; что не удалось найти или скачать и что должен
прикрепить пользователь.
